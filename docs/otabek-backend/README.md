# ⚙️ Otabek — Backend

Твоя зона: `packages/server` (Node + Express + Socket.io). Игровой движок уже написан и работает.
Задача — укрепить его под реальную игру с несколькими телефонами и сохранить результаты.

## Что уже есть
- `src/registerHandlers.ts` — все сокет-обработчики (host + player).
- `src/game/Game.ts` — одна игра: фазы, таймер, скоринг, разбор, лидерборд, подиум.
- `src/game/GameManager.ts` — реестр игр по PIN.
- Полный цикл: лобби → вопрос → ответы → разбор → лидерборд → подиум.

## Твои задачи (по приоритету)
1. **Реконнект** host и игрока по `gameId`/PIN: клиент хранит id в `localStorage`, при обрыве переподключается и получает актуальный статус (сейчас при обрыве host игра закрывается — сделать грейс-период вместо мгновенного закрытия).
2. **Сохранение результатов игры в Supabase** (таблица `games`: pin, host_id, quiz_id, started_at, результат/подиум JSON). Ключ сервисной роли — на бэке, в `.env` (не в Vite). Согласуй схему с XOB.
3. **Устойчивость**: защититься от гонок — двойной ответ, ответ после таймера, старт без игроков, вопрос без ответов (сейчас базово обработано — проверить края).
4. **(Стретч) Конструктор своих квизов**: событие сохранения квиза ведущим → в Supabase → выбор в `Host` рядом со встроенными. Это прямо тема хакатона («конструктор тестов»), большой плюс если успеем.
5. **Мини-нагрузка**: проверить 10–20 одновременных игроков в одной комнате (несколько вкладок/телефонов).

## Правила
- Общие типы и события — в `@codeclash/common`. Добавляешь событие → добавь его в `events.ts` и в типы, чтобы фронт видел.
- Сервер остаётся авторитетным по времени и очкам (клиенту не верим).

## Запуск
```bash
npm run dev:server     # только сервер, :3001, hot-reload (tsx watch)
curl http://localhost:3001/health
```
